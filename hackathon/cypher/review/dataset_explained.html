What is actually inside the Text2Cypher dataset

This is the public dataset neo4j/text2cypher-2025v1, the one our benchmark is built from. Every example below is a real row, rendered exactly as it ships, next to the rows its "correct" query returns when you run it against the live Neo4j database and what our models wrote instead.

950rows in the five databases that are publicly reachable

RETURN m.title AS title, m.released AS release_year, m.votes AS votes
ORDER BY m.votes ASC
LIMIT 5

glm-5p3-flash wrote wrong

MATCH (m:Movie) RETURN m.title AS movie, m.released AS releaseYear ORDER BY m.votes ASC LIMIT 5

MATCH (m:Movie) RETURN m.title, m.released ORDER BY m.votes ASC LIMIT 5

t000 recommendations · hard

List the top 5 actors by number of different genres they've acted in.

Answer key, as published (the "correct" query)

MATCH (a:Actor)-[:ACTED_IN]->(m:Movie)-[:IN_GENRE]->(g:Genre)
WITH a, count(distinct g) AS genreCount
ORDER BY genreCount DESC
LIMIT 5
RETURN a.name AS actor, genreCount AS numberOfGenres

What that query actually returns (5 rows)

actornumberOfGenres
Kurt Russell17
Brad Pitt17
Johnny Depp17
Samuel L. Jackson17
Ewan McGregor16

glm-5p3-flash wrote correct

MATCH (a:Actor)-[:ACTED_IN]->(m:Movie)-[:IN_GENRE]->(g:Genre)
RETURN a.name AS actor, count(DISTINCT g.name) AS genreCount
ORDER BY genreCount DESC
LIMIT 5

kimi-k3 wrote wrong

MATCH (a:Actor)-[:ACTED_IN]->(:Movie)-[:IN_GENRE]->(g:Genre)
RETURN a.name AS actor, count(DISTINCT g) AS genreCount
ORDER BY genreCount DESC, actor ASC
LIMIT 5

Both marked WRONG. Four actors tie at 17 genres. The key picks five without a tiebreaker, so the database returns an arbitrary five. kimi added , actor ASC to make its answer deterministic and got a different, equally correct five.

t002 fincen · medium

What are the names of the top 3 entities that benefited from filings with amounts less than 100?

Answer key, as published (the "correct" query)

MATCH (f:Filing)-[:BENEFITS]->(e:Entity)
WHERE f.amount < 100
WITH e, count(f) AS benefitCount
ORDER BY benefitCount DESC
RETURN e.name, benefitCount
LIMIT 3

What that query actually returns (3 rows)

e.namebenefitCount
Vnesheconombank6
Commonwealth Bank of Australia3
Nomos Bank2

glm-5p3-flash wrote wrong

MATCH (f:Filing)-[:BENEFITS]->(e:Entity)
WHERE f.amount < 100
RETURN e.name AS name, count(f) AS numFilings
ORDER BY numFilings DESC
LIMIT 3

kimi-k3 wrote wrong

MATCH (f:Filing)-[:BENEFITS]->(e:Entity)
WHERE f.amount < 100
RETURN e.name AS name, count(f) AS filingCount
ORDER BY filingCount DESC
LIMIT 3

A genuine model error. Both models filtered on the wrong property. This is what a real failure looks like, and it is the minority.

What this means

Five of the six failures above are the dataset disagreeing with itself: an answer key that returns a different column than the question asks for, an arbitrary choice among tied rows, or a key that answers a different question entirely. One is a real model error.

Across the full 200-question exam, 33 out of every 100 questions are missed by every model we tested, cheap or expensive. That is the ceiling, and most of it is this.
