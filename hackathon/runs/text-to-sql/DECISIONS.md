# Decisions (text-to-SQL run, 2026-11-01 night)

1. **Databases source.** The official Spider zip on Google Drive returned "Quota exceeded" for anonymous downloads. Used the Hugging Face re-host `HAL-9001/spider-databases` (`spider_data.zip`, 206 MB, CC-BY-SA-4.0). Its SHA256 `00636695dabed6b5f4b8328a16b13e069a2f16591d5efcce57660669c85b121b` matched the value published in that repo's README, which states provenance from Drive id `1403EGqzIDoHMdQF4c9Bkyl7dZLZ5Wt6J`. Questions/SQL were taken from the same zip's `dev.json`/`train_spider.json` (identical to `xlangai/spider` on HF, also fetched as a cross-check). No synthetic schemas were needed.
2. **Test set.** 180 rows from Spider dev, round-robin over all 20 dev databases (seed 20261101) so no schema dominates; rows whose gold SQL fails to execute were skipped (none did). Max schema text 519 tokens, well under the 1,500 cap.
3. **Train set.** 450 rows from Spider train (121 DBs, ≤6 per DB, schema ≤450 tokens) so the SFT file stays under 300k tokens (~160k estimated). Spider train and dev databases are disjoint, so no schema leak either.
4. **Scoring.** Execution accuracy with unordered multiset comparison; ordered when gold has ORDER BY (Spider test-suite convention). Column count/order must match the gold projection (strict, like Spider's official exec-accuracy). Exact match is secondary.
5. **Prompt format.** Schema serialized as `table(col type PK FK->t.c, ...)` one line per table; no sample rows, to keep prompts short and cheap.
6. **Reasoning models.** max_tokens 1024 and `reasoning_effort: "low"` where the model supports it (sibling session found glm-5p3 is thinking-only; low effort cuts hidden reasoning from ~600 to ~1-10 tokens).
7. **Account suspension.** At 22:04-22:10 PT every Fireworks call returned HTTP 412 "Account raheeldeal is suspended (monthly spending limit / unpaid invoice)". Only the owner can clear it. All offline phases were completed; paid phases retry every ~15 minutes and are marked partial in RESULTS.md if the account stays down.
8. **Fine-tuning path.** Trained LoRAs can only be served on dedicated deployments (docs: deploying-loras.md, "Serverless deployment is not supported for LoRA models"), which rule 3 forbids, so a managed SFT job on a <16B model could not be scored. Instead: LoRA SFT on the **Serverless Training API** with base `muse-glimmer-30b`, whose LoRA SFT is **free until 2026-11-30** (docs/fine-tuning/models.md note; fireworks.ai/pricing "Training Pricing" banner; cookbook starter checks the same promotion). The resulting sampler checkpoint is scored through the serverless sampler, no deployment. Eval sampling is paid at the training-pool rate ($1.96/M prefill, $4.88/M sampled) and is logged in ledger.csv. The serverless pool has no model under 16B (pool: Muse Spark Open, DeepSeek V4.1 Flash, GLM 5.3 Flash, GLM 5.3, Qwen 3.8 27B, Kimi K3, DeepSeek V4 Flash, Muse Glimmer 30B), so the "smallest under 16B" instruction could not be met with a scoreable result; the free 30B is the documented exception in rule 4. Training file: 450 rows, ~160k tokens, 2 epochs. The equivalent unscoreable managed command would be `firectl sftj create --base-model accounts/fireworks/models/qwen3-8b --dataset t2sql-train --output-model t2sql-qwen3-8b-lora --lora-rank 8`.
9. **Muse Glimmer is a reasoning model.** The system prompt starts with "Reasoning strength: low." (its chat template honors that string); the base eval allows 700 output tokens for thinking, the tuned eval 200 (training targets contain no reasoning channel).
