# Decisions (mcp-tool-pick)

1. **Catalog built by hand** (`build_catalog.py`): 100 tools, 16 servers, ~1,900 tokens as plain text (brief said ~2,500; shorter descriptions kept it readable, catalog is still ~90% of each prompt). Confusable neighbors are inside each server (create/update/delete event; send/reply/forward email) and across servers (reminders.create vs calendar.create_event; fs/drive/github search).
2. **Data generation**: gold tool sampled first, 5 requests per tool in 5 prescribed styles, one glm-5p3 call per tool (100 calls, $0.17) instead of 500 single calls (~$0.65). `reasoning_effort: low` + `json_object` mode. Labels are therefore *not* model-made; glm-5p3 only wrote the text. glm-5p3 is also an evaluated model, so its baseline may be slightly flattered by seeing its own phrasing; noted in RESULTS.
3. **Split**: stratified by tool, seed 2026: 80 tools give 2 rows to test, 20 give 1 (180 test, 320 train). `split_data.py` refuses to overwrite `data/test.jsonl`.
4. **Baseline = model defaults** (no `reasoning_effort`), temperature 0, max_tokens 1024. Turning reasoning down is treated as a harness intervention, not part of the baseline, because it changes cost and latency a lot (nemotron: 843 -> 0 reasoning tokens).
5. **Reasoning knobs** (probed 21:58): `reasoning_effort` "none" works for nemotron, deepseek-v4p1-flash, kimi-k3; GLM-5.3 models reject "none" (HTTP 400, thinking-only) but accept "low"; gpt-oss-120b accepts "low".
6. **Routing confidence** = first-token logprob of the small model's answer (`logprobs: true`). Routing is simulated offline from the small-model and large-model result files on the same rows (no extra calls): for threshold t, rows with logprob < t take the large model's answer and pay both calls. This is exact, since temperature is 0 and both files cover all 180 rows.
7. **Fine-tuning**: no paid SFT budget. Docs confirm Muse Glimmer 30B LoRA SFT is free until 2026-11-30 (docs.fireworks.ai/fine-tuning/models.md and the muse-glimmer cookbook page). The Serverless Training SDK path (which would let me score the adapter without a deployment) needs the `fw-ai/cookbook` repo; cloning it was blocked by this session's permission classifier ("code from external"). Fallback: Managed SFT via the REST API with a *catalog-free* training file (user text -> tool name, ~25k tokens, so even if the promo did not apply the cost would be ~$0.01). The resulting LoRA cannot be served serverlessly and a deployment is forbidden by rule 3, so the row is "not scored (dedicated deployment required)".
8. **Account suspension** at ~22:03 (HTTP 412, monthly spending limit on the shared account) stopped all paid calls after data generation. `run_all.sh` polls every 5 minutes and resumes the remaining phases automatically.
9. **Harder-variant note for the morning**: accuracy saturates at ~98% because each tool has one unambiguous description and requests were generated to need exactly one tool. To create accuracy headroom: 300+ tools with overlapping servers (two calendar providers), multi-tool requests scored as sets, or requests with missing context. The cost headroom (catalog = 82% of cost) exists regardless.
10. **Rate-limit retries**: 65 rows across 12 runs still errored (429) after 5 backoff retries while ten agents shared the account. `retry_errors.py` re-calls only those rows and recomputes the summary; rows with any model response are never re-called, so model behaviour is unchanged. Each JSON records `retried_errors`.
11. **Extra seeds**: `run_all.sh` chose the variance candidate (glm-5p3-flash v2_rubric+5shot) before the retries changed the ranking; after retries v1_plain was best, so its seeds 1 and 2 were run by hand (+$0.10). Both have 3 seeds.
12. **SFT not run**: dataset upload returned 403 "dataset uploads are temporarily disabled, please contact Fireworks AI"; the signed-URL endpoint returned 405. The empty dataset `mcp-tool-pick-20261101-230253` was deleted. Training file `data/train_sft.jsonl` (320 rows, ~36k tokens, catalog-free) is ready and passes the leak check; command in README.
13. **nemotron routing to glm-5p3-flash** (not in the original plan) was added because flash is both cheaper and more accurate than glm-5p3 here; it is the cheapest configuration above 97%.
