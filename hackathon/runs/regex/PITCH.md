# Pitch: English → regex (3 minutes)

All numbers are from RESULTS.md (200-row KB13 test set, execution-based scoring, temperature 0).

1. **Problem and who pays (20 s).** "Every log-search, ETL and validation tool makes users write regexes by hand. Each one takes 5 to 15 minutes and a wrong one is a silent data bug. Product teams want a 'describe it in English' box, but it has to be right, and it has to be instant."
2. **Task and eval (20 s).** "We built a 200-row test set from the KB13 benchmark: an English description, and for each one 10 strings the regex must accept and 10 it must reject. A regex scores only if it gets all 20 right. No judge model, no partial credit, byte-reproducible, and the test set was hashed before any model saw it."
3. **Baseline (20 s).** "Off the shelf, the cheapest useful small model, GLM 5.3 Flash, gets 68%. The frontier open model, Kimi K3, gets 65% at 17× the cost and twice the latency. Nobody is good at this out of the box, because the benchmark has house rules the description never states."
4. **What we changed (40 s).** One diagram: description → small model → regex → compile check → (low confidence?) → large model. "First we read the 57 baseline misses and wrote ten rules: a word is letters only, 'between' works in either order, 'contains' never anchors the line, '3 words' means at least 3. That one system prompt takes the small model from 68% to 95%, and on 100 held-out rows it never saw while we wrote it, from 67% to 90%. Five-shot examples get you 86%. JSON mode makes it worse. A confidence router to the big model buys at most one more row for 2.4× the cost. And a free LoRA fine-tune of Muse Glimmer 30B on 500 training rows is the control: with the plain prompt the untuned base gets 30.5%, the LoRA gets 93.5%. The fine-tune learns the rules; the prompt states them; both land in the same place."
5. **Result (40 s).** The table. "GLM 5.3 Flash with the rubric: 95.0% at $0.12 per thousand requests, 0.57 s median, identical across four seeds. Kimi K3 with the same rubric: 96.0% at $2.64 per thousand, 1.0 s median. One point, which is two rows, and both models miss the same rows, which are label quirks. Same accuracy for 1/21 of the cost."
6. **Business value (20 s).** "At 50k requests a day that is $186 a month instead of $3,956. But the money is in the errors: the rubric cuts wrong regexes from 480,000 a month to 75,000, and at $15 per wrong regex that is $6M a month. The harness is the product; the model choice is the discount."
7. **How far we pushed it (20 s).** The frontier chart. "Prompt alone: +27 points. Few-shot: +18. Routing: the flat line along the top, where every point past the small model costs more and buys nothing. The frontier model does not struggle here; the small model just needed the rules. We would pick this task for its demo-proof eval, not for a model-headroom story."
